Traces a multi-step flow end to end in one call, across language boundaries (Solidity contracts, Rust crates, Noir circuits), from a persistent code index pruned by a relevance judge. MUST reach for this FIRST on any "what happens when…", "how does X lead to Y", "trace the path from A to B", or "which components react to …" question, before `grep` or reading files; then `read` the returned ranges.
`question`: the flow in plain words ("after the committee is finalized on-chain, which components react and what does the selected node emit next?"). `from`: a symbol to start from (`Name` or `Owner::name`) when you already know the first step; otherwise entry points are discovered from the question. `hops`: edges followed from the entries (default 5, max 8). `path`: restrict the walk to a file or directory.
Edges followed, in both directions: publishes / handled-by (Rust `publish`, `Handler<E>`), Solidity `emit` ↔ the Rust code that decodes that event log (names change: `SortitionCommitteeFinalized` → `CommitteeFinalized`), `impl From<A> for B` conversions, Rust calls of Solidity functions, Rust naming a Noir circuit (`"share_decryption"`, `CircuitName::X`), and plain callers/callees.
Output: numbered steps, entry first, each `[lang] Qualified.name  path:start-end  — edge from step k (label)  p=0.xx` plus its signature, then plausible pruned nodes under "Also consider". Steps are candidates, not the complete path: read every boundary hop it reports (decoded by, becomes, calls contract, proves with) and check the "Also consider" entries before concluding.
Limits: links are by name only, so values passed through variables, dynamic dispatch, re-exports under other names, and macros are invisible; the Solidity→Rust and Rust→Noir bridges are heuristics. When no native judge is configured the walk is structural: every edge is followed with fan-out caps and nothing is pruned by relevance (the output says so). When steps look wrong or thin, narrow with `from`/`path` or `trace` a step's symbol with `depth` 2–3.
