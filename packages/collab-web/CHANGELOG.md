## [Unreleased]

### Added

- Added taking a finished bake-off out of the app (see [Design bake-off](../../docs/collab.md#design-bake-off)): *Copy report*, *Share* (where the browser can share) and *Download .md* put the whole result in one Markdown file (`src/components/bakeoff/bakeoff-report.ts`, built in the app from `bakeoff-get` and the cited excerpts: the criteria and instructions, the mode, every entry with its model revealed, the ranking and reasons, both readings and the second opinion, tests, cost, up to 40 cited excerpts as fenced blocks headed `path:line`, and in design mode every design's text; it never names the reviewer, the judge or the writer, a branch, a path or a session id), and, for an implementation, *Download patch* and *Copy patch* per entry plus *Download all patches* (one `.patch` file, winner first, with separators, since the app has no zip helper), disabled with the reason when the entry's code is no longer kept. The companion makes a patch with `git diff --binary` from the commit each entry's worktree was snapshotted into (`scripts/companion-bakeoff-patch.ts`), so it outlives the worktree; the new `bakeoff-patch` request and `canBakeoffPatch` capability carry it (over 5 MB it is refused), and an older companion shows no patch buttons. Shared text and file helpers: `shareMarkdown` in `src/lib/share.ts`.
- Added bake-offs of a folder that is not a git repository (capability `canBakeoffFolder`, the `bakeoff-folder` request, see [Design bake-off](../../docs/collab.md#design-bake-off)): *Bake-off* opens in a *No project* session or any plain folder, lists its bake-offs (empty, not an error, when there are none; keyed by the folder's real path as quizzes are) and starts a *design* bake-off from a pasted document or a text file of the folder, with a one-line note in place of the change, branch, pull request and implementation choices. The challengers and the reviewer read a copy of the folder's text files (`listFolderFiles`/`copyFolderFiles` of `scripts/companion-quiz-folder.ts`); the files the citations name are stored with the bake-off so excerpts still open. *Map this entry*, *Spar with this entry* and *Review again* are not offered there. An older companion keeps today's behaviour, with a plain sentence in place of the "not a git repository" error.
- Added the exports to the mock companion (`scripts/mock-bakeoff.ts`): `bakeoff-patch` with canned patches (one with a binary file), `bk-mock-impl-pruned` (three entries whose code is no longer kept, one whose patch is over the size cap), and with `--topic` a finished design bake-off of the scratch folder of `fhe-statistics` plus `bakeoff-folder`.
- Added *Delete session* (see [Deleting sessions](../../docs/collab.md#deleting-sessions)): *Settle* only moved a row and *End sessions when they settle* only stopped the process, so nothing removed a conversation. *Delete…* is in a row's ⋯ menu, the session's ⋯ sheet and *All sessions*, and *Delete settled sessions…* (with a count) is on the Settled section, all gated on the new optional `canDeleteSessions` capability in the `hosts` frame, so an older companion shows no Delete; rows of vendor agents, rooms and the Personal agent have none. A confirm dialog names what goes (the conversation with its subagents and artifacts, the sidebar entry, the hidden-message marks) and offers *Also remove its worktree* only for a worktree the companion made. The companion (`scripts/companion-delete.ts`) answers the new `session-delete-plan` (what a deletion would meet), `session-delete` (`{ sessionIds, removeWorktree? }`, one result per session: `deleted`, `worktreeKept` with the reason, or `refused` with the reason) and `session-restore` (`{ trashId }`) requests. The files move to `<config>/agent/collab-trash/<trashId>/` (mode 0700, with a manifest), the companion's own records of the session are cleared (sidebar entry as a tombstone every device merges, `sessionOrgRev` bumped; hidden marks; settle records; per-session pull request watch files; the search cache), an *Undo* toast restores all of it for 7 s, and the trash is emptied of what is older than 7 days on companion start and daily. A removed worktree is not undoable: it uses `git worktree remove` without force, a dirty one is reported and kept, and so is one another session also used. A session the companion started is ended first (it waits up to 15 s for it to let go of its file); one running in a terminal, one another omp has open and the Personal agent's session are refused. The device sends session ids only: the companion finds the files itself in its own sessions folder, resolves real paths and refuses links, a session found in two folders and anything outside, uses nothing from a session file as a path, and restoring reads a forged manifest as damaged. Spend history stays (usage totals and charts still count the cost, and omp's `stats.db` is not edited: *All sessions* leaves out a session whose transcript is gone), as do quiz, spar and bake-off records, which keep working without *Show in session*.

- Progress bars and other long unbroken runs in displayed custom messages (such as a background job's result) wrap inside the transcript instead of running off its right edge
- The sessions sidebar's footer keeps every button inside the drawer on tablets: *Start session* takes its own row above the usage, sessions, inbox, diagnostics and devices buttons, which no longer run past the drawer's right edge
- Scrolling up through a long session no longer races to the top and loops. Safari keeps no scroll position when earlier messages load above the view, and the app's own correction anchored on the sticky *N new* pill (which never moves) or on a folded tool run that remounts as it absorbs the earlier calls, so the view stayed near the top and loaded more on every scroll. And when the latest window was barely taller than the screen, the corrected position counted as "back at the bottom", which trimmed the earlier messages again and reloaded them, over and over. The correction now anchors on an entry row that stays mounted, ignores its own scroll adjustments, and only a scroll upward (not the view following new messages, or clamping when the screen grows) loads earlier messages
- A session no longer ends when the host is slow to answer: a connection the host does not welcome, or a snapshot that stops arriving, within 30 s is dropped and retried instead of showing *Session ended* (common when a phone returns from the background)
- With a paired computer, a session follows its omp process to a new room instead of ending: when the host switches sessions, upgrades the room to control, or relaunches its room after losing the relay (a laptop that slept), the app asks the companion for the current link and rejoins, carrying the unsent draft and queued prompts. This also applies on a cold launch of the home-screen app. *Session ended* shows only once the computer no longer lists the process or still reports the ended room after 10 s
- Fixed the transcript losing its bottom position when the on-screen keyboard opens or the composer grows
- Fixed the composer floating above the keyboard by the home-indicator inset, and the connection banner sliding under the status bar in standalone mode
- Fixed slow reconnects after the phone wakes: returning to the foreground or coming back online now retries immediately instead of waiting out a backoff of up to 30 seconds
- Fixed the app staying on a dead connection after a long stay in the background: iOS can suspend the page and leave its sockets open but dead, so on phones and tablets, after 10 s or more hidden (or on any device when the network returns), the session and companion connections are replaced at once, with a delta resume, instead of waiting out the 30 s timers. A short glance away leaves them alone
- Opening a pinned session that the sidebar lists as a recent room made it vanish from Pinned until another session was opened: the sidebar hid the room on screen. The session on screen now stays where you put it (Pinned keeps it, in the same order) and is marked *here*, as a running session is. A room of a process the computer lists is that session's row rather than a second one (so one session is never listed twice), and a pin, snooze or settle you gave such a room carries over to the session's row.
- Fixed an open page failing to open Sketch, Quizzes or another lazily loaded screen with the browser's raw "Failed to fetch dynamically imported module" after the app was rebuilt underneath it (a companion restarted from a checkout, a Pages deploy, an updated `omp` binary), because the chunk it asked for no longer existed. The companion built from a checkout now also serves the content-hashed files of the build kept before the current one (never its `index.html` or service worker), so such a page keeps working. Every lazy chunk load now goes through `importChunk` (`src/lib/stale-build.ts`): it retries once, and if the chunk is still gone the update bar says "The app was updated. Reload to continue." with a *Reload* button, and the sheet says what could not be opened, instead of the browser's message. Nothing reloads by itself, so a draft is never lost. The Inbox's lazily loaded Personal rows no longer take the whole page down when their chunk is missing, and the update bar now sits above open sheets, where its button was covered by the sheet's backdrop.
